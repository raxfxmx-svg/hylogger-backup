07THD003 Data and Display Comparison — 2026-10-16

I compared the earlier PostgreSQL backup and referenced raw/Parquet files with current API responses and deployed frontend logic. This was read-only investigation with new local evidence; it did not change code, databases, configuration, deployment or model training. The conclusions below cover this hole and the listed channels.

All 54,432 sample depths matched. Grp1 sTSAS, Min1 sTSAS and both Final Mask channels each had zero differences in depth_m, value_raw, value_text and value_numeric. All 216 Sections and 36 trays matched in sample and depth boundaries. The 127 source logs retained their IDs, names, metric keys, kinds and availability. Grp1 was mineral_group in both versions; Min1 was mineral_name. The earlier selection error was in the frontend.

The repository anomalies.csv retained 1,200 rows: 1,182 normal and 18 high. All were bound to release fd02659c-dc3d-52ea-a8eb-c032b91e7624. The live release was 1156d65b-384b-539f-882c-c43d5d08fa79, with different revision/axis IDs. The repository route strictly filters those identities, and the live endpoint returned HTTP 200 with items=[] for both all/high requests; an old-identity request returned 404. The local deployment archive's parsed CSV matched the repository. The actual running Lambda CSV/code was not inspected because the AWS session was unavailable, so stale-versus-missing live files remained unresolved.

A separate precision issue was reproducible: etl.py writes depth using Python :g, defaulting to six significant digits, while the anomaly code floors exported depth and the frontend floors full-precision API depth. Applying the same format reproduced all 188 historical anomaly bins, counts and first/last sample numbers. Without rounding, 31 samples changed bins across 16 intervals. For example sample 16577 at 121.99970 becomes 122 in CSV. Original depths were unchanged; export precision changed bin membership. The original model run's full input manifest was unavailable.

Confidence has distinct meanings across components. The current frontend computes dominant valid mineral samples divided by all metre-bin samples. The anomaly model emits percentile scores, flags, score_reliability and coverage; extract.py defines another rule-based confidence; the contract describes a dataset-level Process Level. Those other fields were not integrated into the current adapter. The Django and FastAPI paths are separate, and the 2026-10-07 FastAPI integration had already introduced the current sample-agreement fraction before the later INVALID repair.

Source values remained: 23,201 valid mineral labels, 21,403 INVALID and 9,828 source-null samples. Both masks retained 48,025 ones and 6,407 zeros. A source-null run at samples 13554–13569, 111.62070–111.76449 m, remained present. Whole-metre visualization can hide this finer gap when the metre still has a dominant mineral. Null, INVALID and mask=0 are not automatically geological core loss.

Holding the correct Grp1 selection fixed, excluding INVALID only from candidates changed 113 dominant labels and increased bins below 0.5 from 76 to 150. This was display aggregation, not source reclassification. At 121–122 m, 535 samples included 304 INVALID, 103 null and 90 WHITE-MICA: the valid agreement fraction was 90/535=0.1682. The model's 97.35 anomaly score is a different measure.

Offline replay of the actual deployed adapter against captured responses produced 188 intervals, 150 below 0.5, zero missing-quality intervals and zero anomaly flags. This validates conversion logic, not a reconstruction of an earlier browser screenshot. Sample depths were monotonic with maximum adjacent spacing about 0.01918 m, and no positive gaps were found between the checked tray/Section boundaries. No source interval removal or movement was found.

Next steps identified, but not performed here, were inspection of the running Lambda package, version-aware anomaly regeneration or validated migration, consistent binning precision and separate UI labels for agreement, model reliability and Process Level. This single-dataset comparison cannot establish multi-dataset seam correctness.
